Help me write a Trello task card. If details are unclear, ask clarifying questions before writing.

Use this exact structure:

Title
Short, outcome-focused title (no technical wording).

Context/Problem:
1–2 sentences explaining the context, motivation, or goal behind this work. This does NOT have to describe a problem — it can describe an opportunity, a vision, or the purpose of the feature. Frame it around what the user or business needs, not necessarily what's broken.

Solution:
1–3 bullets describing the feature from a user or product perspective. Do NOT describe implementation, services, endpoints, refactors, or data contracts.

Acceptance Criteria:
2–5 short outcome-based statements describing what the user can see, experience, or do once this is complete.
Write them as simple sentences (not checkboxes).

Rules:

Be brief and direct. No fluff.

Use plain language, not technical jargon.

Focus on visible behavior and business outcome, not how it's built.

Never mention APIs, endpoints, refactors, services, database changes, contracts, or plumbing.

If the task mixes multiple independent changes (rename, export, content, etc.), split them into separate cards automatically.

Keep the entire card under 130 words.

Output raw markdown only.
